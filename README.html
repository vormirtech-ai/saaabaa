<h1>Saba Restaurant Suite</h1> <p><strong>Billing, kitchen order tickets and floor management for fine dining.</strong><br> Runs on the restaurant's own network. No internet, no subscription, no dependencies.</p> </div>

What it is

One small server on a computer in the back office, and a browser on every screen in the building: the captain's tablet, the pass in the kitchen, the till at the front, the manager's laptop. They all read and write the same tables at the same time. Unplug the internet and nothing changes.

It is written in plain JavaScript against Node's own standard library. There are no runtime dependencies at all — nothing to npm install, nothing to compile on the till, nothing that goes stale between now and the restaurant's third year of using it.

What it does

FloorLive plan of every room. Seat, move, merge and transfer tables; covers, elapsed time and running total on each; reservations seated straight onto the plan.
OrderThe carte by course, with modifiers, allergy notes and seat numbers. Fire a course and the kitchen sees it before the captain has put the tablet down.
KitchenA ticket per course per station, timed, with the ones that are running late brought to the front. Bump, recall, reprint.
BillsPrint, split (by seat, by item, or evenly), part-pay across cash, card and UPI, discount with manager approval, void and comp with a reason that is kept.
TaxService charge and CGST/SGST worked out per line, in whole paise, with the rates and the round-off set in one place.
ReportsToday's trading as it happens; the Z report and cash-up at close; thirty days of history; sales by item, by hour, by server and by payment method; a GST summary; CSV export of all of it.
BookReservations with covers, time, table and a note, carried through to the floor plan.
MenuAdd a dish, price it, move it between sections, courses and stations, retire it, and 86 it from anywhere in the building.
SetupThe bill header, staff and their PINs, the service charge and tax rates, the rooms and tables, backups, and the live list of terminals.

Every screen is one of four roles' business — manager, captain, cashier, kitchen — and the server enforces that, not the interface.

Try it without installing anything

There is a demonstration on the web: the whole application, running against a till that lives in your browser tab.

> Open the demonstration → > Sign in as Manager with PIN 1379.

It is built from this directory by tools/build-site.mjs and published by GitHub Pages. Every screen, every figure and every refusal is the product's own code — tests/till/parity.test.mjs runs a service through both the real server and the browser till and fails if a single paisa differs.

What it is not is a place to run a restaurant. A till is a server with a database on the restaurant's own computer; a web page cannot be one, and the restaurant's bills should not be on the public internet in the first place. The demonstration keeps everything in the tab and forgets it when the tab closes.

Getting it running for real

On a restaurant's till (Linux, systemd, Node 22.5+) — the normal way:

sudo ./install.sh

To look at it on a laptop, with a month of trading and a room mid-service already in it:

npm run demo        # then open http://localhost:8080, PIN 1379

Anywhere else, including in Docker if you prefer it:

node server/main.js        # or: docker compose up -d

Each prints the address to open on the tablets, and the manager PIN, once. None of them needs Docker, and none of them needs the website.

Full instructions, including the network and the printers: docs/DEPLOYMENT.md.

Tests

npm test

Eighty-three cases: the pricing and order maths as pure functions, the API against a real server on a real SQLite database over real HTTP, and the published demonstration held against the product it demonstrates. Nothing is mocked. A point of sale is a thing that takes money; a suite that stubs out the database proves only that the stubs work.

npm test unit     # the domain, instantly
npm test api      # a real server per case
npm test till     # the demonstration, against the real thing

Requirements

  • Node 22.5 or newer (22.22 LTS is what the Docker image pins).
  • A computer that stays switched on. A mini PC or a Raspberry Pi 5 is plenty.
  • A wifi network the tablets can reach it on. It does not need internet.
