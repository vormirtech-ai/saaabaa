Billing and kitchen order tickets
for a fine-dining restaurant.

One small computer in the back office. Every screen in the building — the captain's tablet, the pass, the till, the manager's laptop — is a browser against it, all reading and writing the same tables. Unplug the internet and nothing changes.

What it does

Floor

A live plan of every room. Seat, move, merge and transfer tables; covers, elapsed time and the running total on each.

Order

The carte by course, with modifiers, allergy notes and seat numbers. Fire a course and the kitchen has it before the tablet is down.

Kitchen

A ticket per course per station, timed, with whatever is running late brought to the front. Bump, recall, reprint.

Bills

Split by seat, by item or evenly. Part-pay across cash, card and UPI. Discount with a manager’s approval, void and comp with a reason that is kept.

Tax

Service charge and GST worked out per line in whole paise, with the rates set by the restaurant rather than by us.

Reports

Today as it happens, the Z report and cash-up at close, thirty days of history, and CSV exports for the accountant.

How it is built

No dependencies
Plain JavaScript against Node’s own standard library and SQLite. Nothing to npm install, nothing to compile on the till, nothing that goes stale.
No internet
It makes no outbound request of any kind — no telemetry, no update check, no licence call. It cannot stop working because something far away did.
The restaurant’s own data
One SQLite file on hardware the restaurant owns, in an open format, backed up nightly to a directory they can copy anywhere.
Four roles, enforced
Manager, captain, cashier and kitchen. The server checks every request — a captain’s tablet cannot read the day’s takings even if somebody types the address by hand.

Running it

On the restaurant’s own computer, with Node 22.5 or newer:

sudo ./install.sh

That installs it as a service that starts with the machine, puts the database in one directory, sets up a nightly backup, and prints the address to open on the tablets. Docker and a plain node server/main.js both work too, and none of the three needs this website.
